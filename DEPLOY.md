# Deployment (Phase 6)

Four things get deployed independently. Order: **contracts → backend → frontend → nodes**.

---

## 1. Contracts → Polygon Amoy

```bash
# /.env
POLYGON_RPC_URL=https://rpc-amoy.polygon.technology        # or an Alchemy/Infura Amoy URL
PRIVATE_KEY=<deployer key, no 0x>                          # testnet-only wallet
POLYGONSCAN_API_KEY=<optional, for verify>
```

1. Fund the deployer with test POL: https://faucet.polygon.technology (network: **Amoy**).
2. Deploy:
   ```bash
   npm run deploy:mumbai        # config targets Amoy 80002 by default
   ```
   Addresses land in `deployments/mumbai.json`.
3. (optional) Verify:
   ```bash
   npx hardhat verify --network mumbai <MonitorToken addr> "1000000000000000000000000"
   npx hardhat verify --network mumbai <MonitorRegistry addr> <MonitorToken addr>
   ```
4. Note the two addresses — backend and every node need them.

---

## 2. Backend → Render (or Railway / Fly)

A `Dockerfile` is in `backend/`; a Render blueprint is in `render.yaml`.

**Render:** New → Blueprint → point at the repo. Then set the `sync: false` vars in the
dashboard:

| Var | Value |
|---|---|
| `MONGODB_URI` | Atlas SRV string (whitelist `0.0.0.0/0` in Atlas Network Access) |
| `CORS_ORIGIN` | the Vercel URL (fill after step 3, then redeploy) |
| `APP_BASE_URL` | same Vercel URL (used in alert emails) |
| `CHAIN_RPC_URL` | Amoy RPC (only if you want on-chain settlement from the backend) |
| `MONITOR_REGISTRY_ADDRESS`, `MONITOR_TOKEN_ADDRESS` | from `deployments/mumbai.json` |
| `SETTLEMENT_PRIVATE_KEY` | the **registry owner** (deployer) key — it calls `settleConsensus` |
| `RESEND_API_KEY` | optional, for email alerts |

`JWT_SECRET` is auto-generated by the blueprint. Health check: `GET /health`.

**Railway:** New Project → Deploy from repo → set root to `backend/`, it detects the
Dockerfile. Add the same env vars. Expose port 4000.

---

## 3. Frontend → Vercel

New Project → import repo → **Root Directory = `frontend`**. `vercel.json` sets the
framework. One env var:

| Var | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | the deployed backend URL, e.g. `https://depin-monitor-backend.onrender.com` |

After it's live, go back to the backend and set `CORS_ORIGIN` / `APP_BASE_URL` to the
Vercel URL, then redeploy the backend.

---

## 4. Nodes → any machine(s)

On each VM / laptop:

```bash
git clone <repo> && cd <repo>/node-agent
npm install                       # pulls Chromium
cp .env.example .env
```

Set in `.env`:

| Var | Value |
|---|---|
| `BACKEND_URL` | the deployed backend URL |
| `NODE_REGION` | the region this box represents |
| `CHAIN_RPC_URL` | Amoy RPC |
| `MONITOR_REGISTRY_ADDRESS`, `MONITOR_TOKEN_ADDRESS` | from `deployments/mumbai.json` |
| `PRIVATE_KEY` | this node's wallet (leave blank to auto-generate) |
| `SUBMIT_ONCHAIN` | `true` to post results on-chain |

Fund each node wallet with ≥ `minimumStake` MON (transfer from the deployer/treasury)
and with a little test POL for gas, then:

```bash
node src/index.js register
node src/index.js start --dashboard
```

For a genuine distributed demo, run 3–5 of these on different networks/regions.

---

## Post-deploy smoke test

1. `curl https://<backend>/health` → `{ ok: true }`
2. `curl https://<backend>/api/public/network` → node counts
3. Open the Vercel URL → sign up → add a site → within a couple of minutes the
   dashboard shows checks landing and a status.
4. PolygonScan (Amoy) → search the registry address → see `registerNode` /
   `settleConsensus` transactions.
